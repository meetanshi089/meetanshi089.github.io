Four things I built, and what changed

Production work on a live store, so most of the code sits in private repositories. Here is what each piece had to solve.

A bundle builder on the product page

LiquidJavaScriptCart APIAOV

The problem. Customers bought one product at a time. The store had offers running, but nothing on the product page made a second or third item feel like the obvious choice.

What I did. Built a bundle builder from scratch — Buy X Get Y Free and fixed-price discount tiers, a savings summary that updates as you pick, and a quick view so nobody has to leave the page. It hands off straight to checkout. Three versions shipped in the first month.

Migrating the store to a modular theme

Online Store 2.0JSON templatesSections

The problem. The old theme meant a developer had to touch code for routine content changes, and the new theme could not go live until every page matched what customers already saw.

Making the store pass Core Web Vitals

Core Web VitalsLighthouseJSON-LD

The problem. Pages were slow in a way that paid traffic pays for twice — once in ad spend, once in bounced visitors.

What I did. Preloaded the largest image on home, collection and product pages, deferred render-blocking scripts, and cut the Google Fonts request from 18 weights to 2. Added Organization, Breadcrumb and LocalBusiness structured data.

The outage that logged nothing

AWS LambdaAPI GatewayCORSDebugging

The problem. The AI skin test stopped producing reports. No errors in CloudWatch, and curl against the API worked perfectly. From the server side nothing looked broken at all.

What I did. The production API Gateway was missing one custom header in its CORS preflight response. The browser was blocking OTP verification before the request ever reached Lambda — which is why nothing was logged, and why curl passed: curl does not send a preflight. Synced the production config to match, then added CloudWatch 4xx/5xx alarms with SNS alerts so the next failure is noisy.

Result

Before0 reports
Afterrestored
One header. Whole pipeline back.

How I work

Six habits, mostly learned the hard way

01Read the live site firstBefore changing a theme I find out what customers actually see today. Parity is the requirement.
02Check both widthsEvery change gets looked at on mobile and desktop. Most storefront bugs are layout bugs.
03Trust the serverCart totals and gift logic come from what Shopify confirms, never from client state.
04Reproduce in a browserCORS and preflights taught me that curl passing proves nothing about a real user.
05Hand it to marketingPages ship as editable sections. If a copy change needs a developer, I built it wrong.
06Write it downEvery change goes in a log, and anything with a runbook gets one. Future me is a stranger.
